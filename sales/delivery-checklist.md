# 納品前チェックリスト・断る基準

納品の送信はオーナーが行う。AIは本リストで自己点検し、結果を報告する。
法令の数値は、納品ごとに一次情報(国税庁・e-Gov)で最終確認日を残す。本ファイルの数値は例示で、確認日が空欄のものは未確認扱い。

## 1. 共通
- [ ] 依頼内容・範囲・納期・修正回数が、合意した出品プラン/契約と一致している
- [ ] 約束していない機能を入れていない。入れられなかった点は納品メッセージに明記
- [ ] AI補助の利用を、PFの規則と発注者との合意の範囲で開示している(隠さない、「人間のみ」と書かない)
- [ ] 第三者の著作物・フォント・画像のライセンスを確認(出所不明の素材を使わない)
- [ ] 実績・レビュー・経歴を偽って記載していない
- [ ] 納品物に使い方の説明(1ページ)と、確認した前提(税率・日付)を付ける

## 2. 計算の検算
- [ ] 数式・関数を、手計算または別手段で最低5パターン検算(通常値、0、境界値、端数が出る値、最大値)
- [ ] 端数処理は仕様で固定(請求書は税率ごとに1請求書あたり1回の端数処理が原則。国税庁の記載で確認すること)。切り捨て/切り上げ/四捨五入の選択を明示
- [ ] 浮動小数点の誤差対策(整数で計算、ROUND系関数、JSは整数化)。critique.mdで消費税計算が1円ずれた前例あり
- [ ] 検算ケースを表にして納品物またはメッセージに添付
- [ ] GAS: 実行時間・トリガー上限・権限スコープを説明。大量データ向きでない場合は事前に伝える
- [ ] エラー入力(空欄、文字、マイナス)での挙動を確認

## 3. 源泉徴収・インボイスの正確さ
最終確認日: ____(納品ごとに記入) / 確認先: 国税庁 タックスアンサー、インボイス制度特設ページ
- [ ] 適格請求書の記載事項(発行者の氏名/名称と登録番号、取引年月日、取引内容[軽減税率対象は明示]、税率ごとの対価の額と適用税率、税率ごとの消費税額、受領者名)を国税庁の最新ページと照合
- [ ] 登録番号は「T+13桁」。値はクライアントが提供したものだけを使い、ダミーを本物に見せない。サンプルは「T0000000000000」等と明記
- [ ] 源泉徴収: 対象報酬か(税務上の区分)の判断は行わない。計算式と率は、クライアントが指定した前提を使い、国税庁(No.2792等)で率・区分を確認して記載。復興特別所得税を含む率の適用期間を確認
- [ ] 源泉徴収の計算に用いる金額が税抜か税込か(請求書で消費税が区分表示されているか)は、国税庁の記載で確認し、ツール上で前提を表示
- [ ] 2割特例・3割特例・経過措置など時限制度は、適用年と最終確認日を画面に表示し、断定的な「有利/不利」判断を出さない
- [ ] 「あなたは〜すべき」ではなく「入力条件での計算結果」と表現

## 4. プライバシー・機密
- [ ] 納品物・チャットに、クライアントの個人情報・取引先名・金額・マイナンバー・口座番号を、必要以上に求めない
- [ ] クライアントの実データは、公開ツール・公開リポジトリ・公開GAS・共有リンク設定「全員」に置かない。サンプルは架空データ
- [ ] 機密を含むデータを外部の生成AIに貼らない。必要な場合は、匿名化・ダミー化してから。発注者の許可がなければ入力しない
- [ ] 納品後、不要な作業データを削除。GASは権限をクライアントのアカウントへ移管し、自分のアカウントに残さない
- [ ] PFの外での連絡先交換・直接取引の誘導をしない(規約に従う)
- [ ] Webツールは入力値をサーバーに送らない設計か確認(送る場合は明示)

## 5. 納品物の品質
- [ ] スマホ/PC表示、印刷(A4)の崩れ確認、Excelはバージョン(Excel/スプレッドシート)の互換性を確認
- [ ] 数式セルの保護、入力セルの色分け、シート保護の説明
- [ ] 誤字・単位・日付形式(令和/西暦)を確認
- [ ] 記事作成の場合: 事実は一次情報で確認、出典と確認日を記載、AIのみの納品はしない(ops/services.md)

## 6. 断る・範囲外の基準
次は受けない、または範囲外と明示して断る。
1. 税務相談、節税アドバイス、申告書の作成・提出の代行、税務代理、帳簿作成の代行: 税理士法により税理士の業務。ツール・テンプレの提供にとどめ、個別の税額判断は税理士へ案内する
2. 「この取引は源泉徴収の対象か」「インボイス登録すべきか」の個別判断: 断る。計算ツールとしての条件入力に限る
3. 法律・社会保険労務の個別判断(契約書の法的有効性など)
4. 他人の名義・本人確認の代行、規約違反の依頼、レビューの代行・売買、偽の実績づくり
5. 機密情報をAIに入力する前提の依頼で、許可や匿名化ができないもの
6. 納期・品質を保証できない依頼(極端な短納期、仕様が曖昧で上限なし)
7. 医療・金融商品の勧誘、違法・不当な内容の記事
8. 運用保守を無期限で求める依頼(範囲と期間を決めた場合のみ可)

## 7. 納品メッセージ定型
「ご依頼の内容で作成しました。作成にAIの補助を使用し、計算結果は検算ケース(添付)で確認しています。税務上の判断はできません。税額や区分の確認は税理士・税務署にご相談ください。確認した制度の前提は〇年〇月〇日時点の国税庁情報です。」
